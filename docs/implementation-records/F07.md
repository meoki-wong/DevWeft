# F07 — Structured experience feedback

## Delivered

- Added append-only migration v43 with `experience_feedback` records for repository, run/failure reference, failure summary, proposed resolution, applicability scope, evidence, source type, author, verification state, and review time.
- Added `POST /api/testing/experience-feedback`, repository-scoped `GET /api/testing/experience-feedback`, and one-time `POST /api/testing/experience-feedback/{id}/review` APIs.
- Submissions always start `unverified`; only a human `confirm`/`reject` review can transition the status. Confirmed records are not automatically promoted to the shared experience library.
- Validates run/failure repository ownership, JSON shape/size/depth, secret-shaped values, and sensitive field names. Submission and review emit audit events.
- Added a structured resolution form to the diagnostics tab with evidence references derived from the selected run; it explicitly displays unverified status after submission.
- Added SQLite migration v43, PostgreSQL patchup v43, and regenerated `sql/postgres/baseline.sql` to include the new table/indexes.
- Added [EXPERIENCE-FEEDBACK.md](../EXPERIENCE-FEEDBACK.md) with request examples and review semantics.

## Verification

- `npx vitest run test/experience-feedback.test.mjs test/cloud-testing-evidence.test.mjs test/postgres-baseline.test.mjs --reporter=dot` — 3 files, 59 tests passed, including PGlite baseline/patchup checks.
- Tests cover repository scoping, default unverified state, human review metadata, duplicate review rejection, secret/key validation, and UI submission with run evidence.
- `node scripts/gen-postgres-baseline.mjs` — generated PostgreSQL baseline with 78 tables, 66 indexes, SQLite migration version 43.
- `node --check` passed for migration, service, API, and dashboard UI files.

## Limits

- Feedback review is one-time. Corrections should be submitted as a new feedback record so the original review remains traceable.
- PostgreSQL schema generation and PGlite patchups were exercised; a real PostgreSQL deployment was not.
- The existing dashboard deployment boundary remains the access control boundary; authentication design was not changed.
