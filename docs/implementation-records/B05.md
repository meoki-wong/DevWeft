# B05 — 本地发布验证

## 交付

- 新增 `npm run verify:release` 和 `scripts/verify-release.mjs`，不依赖 Jenkins、GitHub Actions 或 GitLab pipeline。
- 门禁扫描已跟踪及未忽略文件中的旧品牌与高置信度凭据格式，拒绝 Jenkins、GitLab CI、GitHub Actions、Azure Pipelines、CircleCI、Bitbucket Pipelines、Buildkite、Travis、AppVeyor、Drone、Woodpecker、Semaphore、TeamCity、Harness、Tekton 等常见 pipeline 配置路径，以及退役 MR client；校验 JSON、OpenAPI YAML、package/lockfile 一致性、Node 版本、运行依赖树和四个 Windows CMD 入口。
- 完成结构检查后运行整套 Vitest；`--audit` 可选启用需联网的完整 npm 依赖审计（runtime + dev），按 high 阻断并打印低于门槛的 advisory。

## 验证

- `npm run verify:release -- --audit` 通过：静态公开残留检查、23 个 JSON、OpenAPI YAML、依赖树和四个部署入口均通过。
- 全量测试：133 个文件通过，1109 项通过、6 项跳过。
- Runtime audit 未发现 high/critical；保留一项尚未修复的 `sprintf-js` 中危上游 advisory，详见 [`DEPENDENCIES.md`](../DEPENDENCIES.md)。
- 最新 `npm run verify:release -- --audit`：完整 runtime/dev 审计与全量测试通过；147 个测试文件、1185 项通过、7 项环境跳过。常见 CI 配置路径正反例检查和样例 build 输出忽略检查通过。审计仍报告同一依赖链的 2 条中危记录，没有 high/critical advisory。
- `git diff --check` 通过。

## 限制与后续

- `--audit` 需要可访问 npm registry；不带参数的验证仍可在本地离线运行。
- Windows CMD/PowerShell 与 Hyper-V 必须在实际 Windows 主机补充验收；本地静态门禁只验证入口文件存在且非空。
