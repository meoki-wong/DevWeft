# D05 — 真实主机矩阵

## 交付

- 新增 [`REAL-HOST-ACCEPTANCE.md`](../validation/REAL-HOST-ACCEPTANCE.md)，覆盖 SQLite 单机、外部与 embedded PostgreSQL、签名 Hyper-V 镜像、网络 fail-closed、双机共享 PG、控制面停机、blob 故障恢复，以及数据库/blob 分开备份恢复。
- 为每个场景给出运行步骤、预期状态码/字段/PM2 进程、退出码和需保留证据；对可能改变 Windows 网络或服务状态的冲突注入明确要求隔离测试 VM。
- 提供不含秘密的运行信息表、W01–W09 结果表和证据脱敏规则。明确把未运行项标记为未运行，不用单元测试或 PGlite 代替实机结果。
- 验收文档记录 2026-10-15 当前实施环境为 macOS；用户可提供主备环境，但当前不在内网，暂时无法连接目标主机和数据库。

## 设计决定

- D05 的可交付项是可由目标环境操作人复现的矩阵与证据模板；没有真实主机时，真实运行结果保持待填写，不能标为通过。
- Hyper-V 镜像必须来自用户有权使用的 Windows 安装环境；仓库不提供 OS 镜像。主备必须用真实共享 PostgreSQL 与真实 blob endpoint 验收。
- 主机控制面故障与 blob 故障分别注入，验证主机本地控制面 readiness 与备用上传通道的独立状态。主机数据丢失场景只审查/演练恢复计划，不以破坏性操作模拟。

- D04 定向测试：6 个测试文件、53 项通过。
- 最新全量发布检查：`npm run verify:release -- --audit` 通过，147 个测试文件、1185 项通过、7 项环境前置条件跳过。
- 单独联网审计：完整 `npm audit --audit-level=high` 未发现高危/严重项；仍报告 `@open-policy-agent/opa-wasm → sprintf-js` 的 2 条中危依赖记录。上游尚无修复版本，强制降级 OPA 属于破坏性变更，因此保留并在依赖清单中说明。
