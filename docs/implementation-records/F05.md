# F05 — Run comparison

## Delivered

- Added `GET /api/testing/runs/{runId}/compare?against={otherRunId}` and a Run comparison tab in the evidence dialog.
- Comparison reads same-repository runs, their stored checks, and frozen binding references to suite lock, required case set, profile digest, image manifest digest, and policy digest.
- Reports added/removed cases first, then common-case status changes, failed checks, elapsed time, and denominators.
- Marks whole-run comparison direct only when repository, unit, side, purpose, frozen configuration, and observed check-key set all match. Otherwise it shows explicit reasons while retaining available per-check evidence.
- Added [RUN-COMPARISON.md](../RUN-COMPARISON.md) with API and metric semantics.

## Verification

- `npx vitest run test/compare-runs.test.mjs test/cloud-testing-evidence.test.mjs test/dashboard-testing-read.test.mjs --reporter=dot` — 3 files, 65 tests passed.
- Cases cover comparable same-lane runs, changed case sets and frozen config, cross-repository rejection, missing and identical run IDs, and UI display of the incomparability reason.
- `node --check testing/compare-runs.js` and `node --check public/assets/cloud-testing/evidence-dialog.js` passed.

## Limits

- The denominator is the count of reported checks, not expected-but-unreported checks; suite coverage remains represented by run evidence elsewhere.
- Dashboard comparison is constrained to the current formal round in the UI; callers may use the API to compare any two runs in the same repository.
- Only SQLite fixtures and the local browser DOM harness were exercised.
