# B03 — 数据备份和恢复

## 交付

- SQLite 走在线 backup API，输出前执行 `PRAGMA integrity_check`；源库不存在立即以非零码失败。
- PostgreSQL 输出 custom-format archive，用 `pg_restore --list` 校验；缺少 URL、工具或数据库连通性时失败，不生成成功清单。
- 每个备份旁边生成 `.manifest.json`，记录格式版本、数据库方言、时间、文件名、字节数、SHA-256、schema 版本、完整性结果和本地 blob 文件清单/哈希。
- 本地 blob 文件作为备份旁边的 `.blobs/` 目录存储；拒绝符号链接。保留策略会成组清理数据库、清单与 blob 目录。
- 新增 `npm run restore`：先检查清单、SHA-256、数据库 integrity、迁移账本与 schema 版本；SQLite 支持 dry-run、恢复到新路径、显式 `--force` 覆盖与 timestamped 原库副本；PG 用单事务 `pg_restore` 且必须显式 `--force`。
- ONBOARDING 增加可复现备份/恢复步骤和停服/WAL 注意事项。

## 验证

- `npm test -- --run test/backup-restore.test.mjs --reporter=dot`：2/2 通过，覆盖全迁移 SQLite 库、数据恢复、blob 恢复、dry-run、覆盖保护、原库保留副本、篡改 hash 拒绝和缺失源库非零退出。
- `node --check` 检查了备份、恢复与 manifest 模块。

## 限制与后续

- 当前环境没有 `pg_dump`/`pg_restore` 可执行文件，PostgreSQL archive 的真实工具链和服务恢复尚未在此机器实跑；工具可用的部署环境必须验证到 scratch database。
- PostgreSQL restore 是目标数据库对象替换操作，须停写、先另做备份，并用 `--force` 明确确认。
- SQLite restore 需要先停止 DevWeft；如果目标仍有 `-wal`/`-shm` sidecar，命令会拒绝操作。
