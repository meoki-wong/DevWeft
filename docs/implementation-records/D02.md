# D02 — PostgreSQL 安装与连接

## 交付

- 新增 PostgreSQL 支持模块，统一执行 PostgreSQL 15+ 版本门槛、连接检查、schema/baseline 检查、角色成员关系和 RLS 检查。`awp_tenant` / `awp_worker` 必须是 NOLOGIN、NOSUPERUSER、NOBYPASSRLS；不满足时停止预检并指出需要 DBA 修复。
- 新增 `npm run postgres:check`：支持 `--connection-only`、`--schema-only` 和 `--require-backup-tools`，输出版本、迁移前置条件和 `pg_dump` / `pg_restore` 工具状态，不打印连接 URL 或密码。
- 将 PostgreSQL 版本与统一 schema 检查接入既有部署预检；迁移前拒绝低于 15 的服务器，并区分仅连接、迁移前和迁移后完整检查。
- PostgreSQL 备份与恢复在 Windows 自动查找可选 bundled PostgreSQL 工具；其他平台从 `PATH` 解析。调用 libpq 工具时移除 URI 密码并通过 `PGPASSWORD` 传递。
- Windows 内置单机安装在 `initdb` 前检查目标目录、写权限、可用空间和端口。目录非空但缺少 `PG_VERSION`、端口被其他进程占用、已有配置 URL 指向外部服务器时停止；已有集群只检查并复用，不运行 `initdb` 或删除数据库目录。低于 5 GB 可用空间时给出扩容提示。
- RLS bootstrap 不再新建当前代码未使用的 `awp_admin BYPASSRLS` 角色；保留既有数据库角色不作删除或变更。外部 PostgreSQL 指引说明角色是 cluster-wide、DBA 预创建/授权方式、数据库 owner 的迁移职责，以及 Ubuntu、macOS、Windows 客户端工具准备方式。

## 验证

- `test/postgres-support.test.mjs` 和 `test/rls-tenant.test.mjs`：15 项通过，覆盖版本边界、旧版本拒绝、连接错误脱敏、RLS/bootstrap 完整检查、过权角色拒绝、Windows 工具路径解析和本地初始化保护的静态契约。
- `test/backup-restore.test.mjs`、`test/deployment-entrypoints.test.mjs`：与 PostgreSQL 变更相关的回归用例通过。
- `AWP_DB_DIALECT=sqlite AWP_PG_URL= npm run postgres:check`：返回 SQLite 未配置 PostgreSQL 的明确信息并成功退出。
- `npm run verify:release`：通过；136 个测试文件通过，1123 项通过，6 项因缺少真实 PostgreSQL、Playwright 包或 Chromium 前置条件而跳过。发布扫描、配置契约、依赖树和全量测试均通过；联网 audit 未在本包重复执行。
- `git diff --check` 通过；Git 仅对既有 CMD/PowerShell 文件报告仓库属性指定的 LF→CRLF 转换提示。

## 限制与后续验收

- 当前环境没有 `pwsh` / Windows PowerShell、CMD、Windows 主机或 Hyper-V；安装脚本只完成静态契约验证，不能宣称通过 Windows 实机。
- 当前环境没有 `pg_dump` / `pg_restore` 或独立 PostgreSQL 服务；PGlite 验证了 PostgreSQL schema/role/RLS 契约，但无法替代真实 PostgreSQL 连接、原生备份恢复和托管数据库权限验收。真实平台矩阵放入 D05。
- PostgreSQL 最低版本固定为 15；发布时应依据 [PostgreSQL supported-version policy](https://www.postgresql.org/support/versioning/) 复核该下限和客户端工具版本。安装说明链接到 PostgreSQL 官方 Ubuntu/macOS/Windows 下载页与 Homebrew formula。
