# F01 — 项目接入 CLI

## 交付

- 新增 `devweft project add [path]`，识别 Git worktree 根目录和 package 名；支持 `--slug`、`--config`、`--apply` 与 `--dry-run`。
- 默认 dry-run，只输出项目根、目标配置路径和将写入的 profile 摘要，不创建文件。`--apply` 将 profile 写到平台的忽略文件 `data/repo-platform.json`（或显式配置路径）。
- 配置原子写入；重复 apply 对已相同配置不重写；更新已有 profile 时保留 suite/smoke 和其他项目；参数、非 Git 路径、坏 JSON 与 slug 错误均明确失败。
- 命令只本地读取 Git/package 元数据，不连接远端、不读取 remote URL、不上传源码或密钥。CLI 输出不回显已有 profile 的自定义字段。
- 注册 npm bin 与 `npm run devweft` 入口；README 增加 dry-run/apply 用法；`.gitignore` 显式忽略生成的本地仓库 profile。

## 设计决定

- profile 写入平台本地 `data/repo-platform.json`，而不是修改被接入仓库，避免 CLI 改动用户项目或把机器路径写进开源仓库。
- 新接入不自动启用 smoke sides，也不假设测试 suite 已存在；用户按项目能力逐步补充测试配置。
- 本地路径保存为绝对路径，避免平台运行目录不同导致 workspace 漂移。`AWP_REPO_PLATFORM_CONFIG` 可通过环境变量或 `--config` 覆盖默认目标。

## 验证

- `node --check bin/devweft.js`：通过。
- `npx vitest run test/project-add-cli.test.mjs test/repo-platform.test.mjs test/public-defaults.test.mjs`：3 个文件、15 项通过，覆盖 dry-run 不落盘、原子 apply、重复幂等、已有配置保留、非法输入、help、生成文件忽略规则和零上传声明。
- `npm run devweft -- project add --help`：帮助文本和 npm 脚本入口可执行。
