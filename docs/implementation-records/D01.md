# D01 — 部署 profile 与预检

## 交付

- 统一部署配置为忽略提交的 `data/deploy.env`，新增公开示例 `data/deploy.env.example`。Node 通过 `--import` 预加载器读取此文件，PowerShell 通过共用解析器读取；旧 `scripts/deploy.env` 只在 canonical 文件不存在时迁移一次。
- `data/node.env` 保留为备用机 profile，要求共享 PostgreSQL、合法监听端口，并通过显式 blob URL 或共享数据库的看板主链路确定远端存储。
- 新增 `scripts/preflight.ps1` 的 `deploy`、`standalone`、`primary`、`standby` 检查；共用 helper 校验 Node.js 22.12/24/26+、npm、Git、环境文件语法、数据库类型和端口。
- 四个 CMD 入口继续分别执行全量部署、单进程前台启动、主机服务启动和备用机服务启动。管理员提权流程等待子进程并转发实际退出码；启动命令在启动服务前执行 profile 预检。
- PowerShell 部署/主备脚本使用单一配置读取路径。首次部署保留现有配置值，并生成/更新到 `data/deploy.env`；端口和 Git remote 可由示例配置驱动。
- README/ONBOARDING 更新统一配置文件、Node 版本和角色配置说明。

## 限制与后续

- 当前执行环境是 macOS，没有 Windows PowerShell、CMD、管理员 UAC 或 Hyper-V；PowerShell/CMD 只做了静态检查和契约测试，必须在 Windows 主机完成 D05 实机验收。
- 6 个测试跳过由测试内的环境条件触发，涉及不可用的独立 PostgreSQL、离线 Playwright 包或 Chromium；它们未被统计为通过。

## 后续修正

- 备用节点可在显式 `AWP_BLOB_BASE_URL` 之外，使用共享数据库中看板链路池保存的非 loopback 主链路地址；CMD 启动预检不再要求重复填写 URL。
- 启动后的 readiness 仍真实探测共享 PostgreSQL schema 与远端 blob endpoint。缺少可用地址或服务时保持失败关闭；主备 failover 场景仍推荐显式配置独立 blob 端口 `8792`。
