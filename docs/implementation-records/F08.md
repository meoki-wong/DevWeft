# F08 — Evidence-backed trends

## Delivered

- Added `GET /api/testing/trends` with repository, date range, day/week buckets, and optional unit/side filters.
- Added a dashboard page with rates, denominators, run bars, daily detail, skipped checks, incomplete coverage, no-evidence runs, and duration.
- Check pass rate excludes skipped/unknown states. Gate pass rate requires complete coverage and at least one result check. Missing denominators return `null` and display as unknown.
- Added [TESTING-TRENDS.md](../TESTING-TRENDS.md) documenting date and metric semantics.

## Verification

- `npx vitest run test/testing-trends.test.mjs test/contracts.test.mjs test/docs-freshness.test.mjs --reporter=dot` — all 3 files passed after correcting a bucket-specific expectation; trends tests cover skipped, incomplete, empty evidence, failure/error checks, duration and date/bucket bounds.
- `node --check testing/trends.js`, `node --check dashboard/testing.js`, and `node --check public/assets/dashboard.js` passed.

## Limits

- The endpoint reports observed checks and the existing `coverage_complete` marker; it cannot estimate missing cases when that marker is absent.
- Trend data was tested with deterministic fixtures in SQLite service tests. No production workload or visual browser screenshot was exercised.
