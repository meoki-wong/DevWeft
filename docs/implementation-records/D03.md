# D03 — 虚拟机与网络配置

## 交付

- Hyper-V worker 改为明确 opt-in：`AWP_HYPERV_ENABLED=false` 是默认值。未准备签名 runner image 时可直接部署和启动控制面；PM2 配置不会启动 `awp-host-worker`。Fresh deploy 只在 opt-in 后检查/启用 Windows Hyper-V feature；需要重启时保留 opt-in 配置，重启后可继续部署。
- 新增可配置 `AWP_VM_NETWORK_CIDR`，限制为规范的 RFC1918 IPv4 `/24`。`.1` 是代理，`.10` 是单 VM 默认地址，`.11`–`.26` 是并行 guest 地址池；主机网络、guest worker、worker PM2 环境和文档共享配置。
- 重写 Hyper-V 网络部署 helper。`-PreflightOnly` 只读检查精确匹配的 Hyper-V switch/adapter、防火墙规则、主机 IPv4 地址和路由重叠。已有 switch 不是 Internal、网络重叠、adapter 地址冲突、同名防火墙规则不匹配时会带错误码停止。
- 网络设置只重用完全匹配的 Internal switch/IP/firewall rule，或创建缺失资源；不删除/转换已有 switch，不移除 IP/路由，不禁用 IPv6，不删除/重建防火墙规则。VM 主机 worker 会先验证 active image 的签名和 VHDX 哈希，再进行网络检查/代理启动。
- 部署复制 runner 证书时改为哈希比对：一致则复用，不一致则报 `RUNNER_CERT_CONFLICT`，保留目标文件。移除了 `C:\awp-runner` 默认根目录，使用 `AWP_RUNNER_ROOT` 或仓库下 `data/runner`；同时不再修改源 Golden VHDX 的只读属性。
- 修复 `image:publish` 的异步 SQLite/PostgreSQL 数据库操作和未打开数据库时的关闭处理。发布必须提供与 image ID 对应、含实际组件和版本的 SBOM；新增 `image:sbom`、`image:verify` 命令。active 发布在事务内登记新镜像并退役旧镜像。部署、主机启动和 worker lane 都检查签名 manifest 与 VHDX 内容。
- 补充 Windows 部署/镜像操作流程、冲突处理、地址规划和真实 Windows 验收限制。

## 设计决定

- 控制面默认不要求 Windows、Hyper-V 或预制 VHDX。VM worker 使用者先启动控制面，再将自己有权使用的 Windows VHDX、组件清单及数据库镜像登记准备好，最后设置 `AWP_HYPERV_ENABLED=true`。
- 网络冲突采用 fail-closed：报出冲突接口/路由/规则并要求操作人手动选择新 CIDR、交换机名或人工处理配置，不自动“修复”用户的主机网络。
- 地址段仅允许 RFC1918 `/24`，保证主机 `.1`、guest `.10` 和 `.11`–`.26` 池在子网内，不把网络规划扩展成任意网段/掩码功能。
- 镜像每次升级使用新 image ID，先可选 canary，再 promote；旧 active 镜像保留作 rollback 点。

## 未实机验证与后续

- 当前执行环境是 macOS，没有 Windows PowerShell、CMD、管理员 UAC、Hyper-V、独立 PostgreSQL 服务或 `pg_dump`/`pg_restore`。因此网络 helper 只经过静态契约检查，不能宣称已通过 PowerShell parser、Windows 网络变更或真实 guest boot 验收。
- D05 需在真实 Windows 主机验证空白部署、显式启用 Hyper-V、交换机类型冲突、LAN/VPN 子网冲突、同名防火墙冲突、镜像缺失/哈希不匹配、证书冲突，以及合法镜像的 guest 启动和网络策略。
- 需要真实 PostgreSQL 与 Windows embedded PostgreSQL 的镜像发布/verify 和镜像生命周期测试；单元测试覆盖 SQLite，PostgreSQL 使用仓库现有契约验证，不能替代真实服务。
