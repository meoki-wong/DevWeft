# F02 — 测试模板与 schema

## 交付

- 新增 [`project-config.schema.json`](../../schemas/project-config.schema.json)，以 JSON Schema Draft-07 描述项目上下文配置、check ID/name、argv 参数数组及 1–600 秒超时范围；使用 AJV 做标准 schema 校验，并额外拒绝重复 check ID/name。
- 新增 `node-unit`、`playwright-web`、`http-api` 三个模板。每个 check 都是 executable + args 的数组，不拼接 shell 字符串；模板写入项目 `.awp/config.json` 并带 `$schema` 链接。
- 扩展 `devweft project template`：默认 dry-run，`--apply` 原子合并到现有项目配置；重复执行幂等；同 ID 但配置不同则停止，不覆盖手工配置。新增 `devweft project validate` 输出结构化 schema 诊断并以非零退出码拒绝无效配置。
- 更新 guest `runTenantChecks` 使用 `spawnSync(executable,args,{shell:false})`，校验非空 argv、timeout 边界并拒绝直接 shell executable；旧 `checks[].script` 不会执行，需迁移为 `checks[].command`。
- 更新依赖清单和 README，写明 Playwright 模板依赖项目自行安装 `@playwright/test`，HTTP API 模板默认查找 `tests/api`。

## 设计决定

- 模板作用于目标仓库的 `.awp/config.json`（若已有根目录 `awp.config.json` 则合并到优先读取的该文件），而 F01 的 repo-platform profile 保持平台本机路径配置，两者用途分开。
- 执行 argv 时显式 `shell:false`；模板直接使用 Node 可执行文件，避免 Windows `.cmd` 和 POSIX shell 差异。用户可在自己的 Node 测试文件中封装项目逻辑。
- 现存的任意 shell 字符串不再执行。这是安全与跨平台边界变化；运行时失败提示要求转为 argv 数组，不静默把旧命令标记通过。
- AJV 仅在平台 CLI/验证模块作为直接运行依赖；guest 自包含 runner 对必要 argv 字段作本地 fail-closed 检查，不要求 golden image 预装 AJV。

## 验证

- 定向：`npx vitest run test/project-config.test.mjs test/project-add-cli.test.mjs test/tenant-config.test.mjs test/guest-static-vitest.test.mjs test/testing-m1.test.mjs` — 5 个测试文件、43 项通过。
- `npm run verify:release` — 141 个测试文件、1158 项通过、6 项环境前置条件跳过；残留、JSON/OpenAPI、lockfile 和依赖树校验通过。可选联网 audit 未纳入 release gate。
- `npm audit --omit=dev` 确认 OPA WASM 的既有依赖链仍命中 `sprintf-js` 中危上游 advisory；降级 OPA 会是破坏性变化，未自动套用 `--force`。依赖清单保留该风险说明。

## 未验证与后续

- Playwright 模板需要使用者项目安装 `@playwright/test` 并准备所需浏览器；本轮不安装或下载用户项目依赖。HTTP API 模板需要仓库创建自己的 API 测试。
- 本地模板 apply 和验证在当前 macOS Node 22 环境通过；Windows guest 下各执行器的实际行为继续纳入 D05 主机矩阵及 F02A 的跨平台取消/超时验证。
