# X01 — Extension contracts

## Delivered

- Added `extensions/contracts.js` with validated `GitProvider`, `DesignSource`, `RunnerBackend`, and `BlobBackend` contracts, a small registry, and stable normalized error codes including retryability for transient failures.
- Added `extensions/adapters.js` builders for runner and blob backends.
- Added a generic Git provider as the default and adapter injection points for testing routes and Lanhu tools. The design-source default is offline; the optional Lanhu connector is disabled until `AWP_LANHU_MCP_URL` is explicitly set.
- Wrapped local filesystem and standby HTTP blob storage in the blob contract. Runner selection is explicit: Hyper-V is the PM2 host-worker default; local process execution is opt-in, limited to the supported static lane, and is not VM isolation.
- Added an offline design-source fixture at `examples/extensions/example-design-source.mjs` and documented adapter registration and test expectations in `docs/EXTENSIONS.md`.

## Design boundaries

- Adapters do not receive data beyond their method arguments and cannot broaden existing repository, permission, secret, or isolation checks.
- Unsupported, unavailable, and failed provider operations must remain explicit failures; they are not converted to successful empty results.
- The ordinary test suite uses offline fixtures. Live provider integrations and real host infrastructure are separate environment acceptance work.
